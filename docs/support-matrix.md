# Support matrix: what this family adds

Story 1.6. This is a delta on Fire Temple's [support matrix](../../firetemple/docs/support-matrix.md), which covers WebGPU itself, the browsers that ship it, `rgba16float` targets, timestamp queries and the HDR canvas, and on Snow Temple's [delta](../../snowtemple/docs/support-matrix.md) (`read_write` `r32float` storage textures, storage atomics, `float32-filterable`). This page covers only what Star Temple leans on beyond those.

**Checked so far:** headless Chrome 156 on an Apple M1 Max (Metal 3), probed on 2026-10-29 by `node experiments/support-probe.mjs` from the dev server ([support-probe.json](studies/support-probe.json)), plus Dawn under Node for the tests and studies. Safari, Firefox, Windows, Android and an integrated GPU are not checked yet; they belong to the device matrix (story 10.2). Spec facts are from the WebGPU and WGSL specifications, not measured.

## What it means for the plan

- **Nothing in M0 or M1 needs an optional feature.** Stars blend into `rgba16float`; trails are computed in closed form (2.5), so no float accumulation target is needed.
- **Blending into `rgba32float` is a feature, not a given.** The spot test first drew into `rgba32float` and drew nothing, because the test device does not request `float32-blendable`. Chrome offers it on this Mac; elsewhere it must not be assumed.
- **A solar system must be drawn relative to the camera.** At 1 AU a position stored as f32 world coordinates is good to 16 km, and at Neptune to 524 km: a planet a few hundred kilometres across, seen from close by, would jump between pixels. `orbits` keeps positions in f64 on the CPU and hands the shader positions relative to the camera, which are small where it matters (the floating origin of the plan's Decisions).
- **A million stars fit in one buffer with the default limits.** 32 MB is under the default 128 MiB binding size, so the large-count paths need no raised limit.
